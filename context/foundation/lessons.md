## Toggle analytics off to work around Colima's vector-sidecar mount failure

- **Context**: Local Supabase dev stack (Colima) — any phase/change that runs `npx supabase start` locally under Colima.
- **Problem**: Under Colima, `supabase start` can fail with "failed to start docker container supabase_vector_<project>...mkdir ...: operation not supported" because Colima's docker.sock lives inside the virtiofs-shared home directory and can't be bind-mounted into the nested vector/analytics container. This blocks local verification and can look like it was caused by the current change, even though it's a pre-existing environment issue.
- **Rule**: If `supabase start` fails with a 'vector'/docker-socket mkdir error under Colima, first reproduce on the pre-change config.toml to confirm it's environmental, not a regression; then work around it by temporarily setting `[analytics] enabled = false` in supabase/config.toml, running `supabase start`, and re-enabling it afterward. Do not symlink `/var/run/docker.sock` or otherwise touch the system Docker socket without explicit user approval.
- **Applies to**: all

## Override shadcn's default theme tokens to match this app's dark-only look

- **Context**: Any new shadcn/ui component added to this project (e.g. Dialog, Popover, Tooltip, Select) — components sourced from `npx shadcn@latest add`.
- **Problem**: shadcn components default to light-theme CSS variable tokens (`bg-background`, `text-foreground`, `text-muted-foreground`, `bg-secondary`) from `src/styles/global.css`, but this app never toggles the `.dark` class — its dark look comes entirely from explicit Tailwind utility classes. A newly added Dialog (`context/changes/goals-page-ux-consolidation`) rendered with a white background, making its dark-styled contents (`FormField`'s white text) invisible. Root cause: the light/dark token system generated by the shadcn scaffold is unused infrastructure — the app hand-builds its dark "cosmic" look instead of activating dark mode, so any component written against those tokens defaults to light until manually overridden. A proper fix (rewriting `:root`/`.dark` in `global.css` to encode this app's actual palette) is tracked as a follow-up; until that lands, this per-component workaround is required.
- **Rule**: When installing or using a new shadcn/ui component, always override its default token-based classes (`bg-background`, `text-foreground`, `text-muted-foreground`, `bg-secondary`/`text-secondary-foreground`, etc.) with the app's explicit dark palette (`text-white`, `bg-neutral-900` or `bg-white/10`, `border-white/10`, `text-blue-100/60`) rather than assuming it already matches the app's look.
- **Applies to**: implement, plan-review
